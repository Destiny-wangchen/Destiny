## 主诉

两个症状，看起来毫不相干，其实是同一套机制：

```c
int *make(void)
{
    int a[3] = {1, 2, 3};
    return a;              /* 返回局部数组的地址 */
}

int main(void)
{
    int *p = make();
    printf("%d\n", p[0]);  /* 有时 1，有时乱码，有时崩 */
}
```

另一个：

```c
int f(int n) { return n == 0 ? 0 : n + f(n - 1); }
```

算 `f(100000)` 直接退出，什么也没打印。

一个返回了不该返回的地址，一个递归太深，两件事都发生在栈上。

## 化验一：地址一层比一层小

```c
#include <stdio.h>

void inner(int depth)
{
    int here = 0;
    printf("第 %d 层 = %p\n", depth, (void *)&here);
    if (depth < 3) inner(depth + 1);
}

int main(void)
{
    inner(1);
    return 0;
}
```

```text
第 1 层 = 000000000062FE1C
第 2 层 = 000000000062FDDC
第 3 层 = 000000000062FD9C
```

每深一层，地址少 `0x40`，也就是 64 字节。这 64 字节就是这一层函数的"房间"，术语叫**栈帧**。

## 化验二：一万层能跑，一万五千层就崩

```c
static void down(long d, long limit)
{
    char pad[100];          /* 每层压 100 字节 */
    pad[0] = (char)d;
    if (d < limit) down(d + 1, limit);
    else printf("深度 %ld 层，活着回来\n", d);
}
```

用不同深度跑：

```text
深度 5000 层，活着回来
深度 10000 层，活着回来
exit=-1073741571     ← 15000 层
```

一万层没事，一万五千层就崩，退出码还是第 01 例那个 `0xC00000FD`。1 MB 的栈 ÷ 每层约 100 字节 ≈ 一万层，和实测对得上。

## 诊断：一个栈帧里装了什么

每次调用函数，机器会做四件事：

1. 把返回地址压栈，也就是"函数跑完该回到哪一行"；
2. 把调用者的栈底指针存下来，结束时好恢复；
3. 给参数和局部变量划地方，包括那 64 字节里被浪费的填充；
4. 栈指针往下挪，交出这块地。

函数返回时，栈指针直接挪回去。**注意"挪回去"不等于"清空"**，里面的数据还在，只是不再属于这个函数了。

这就解释了 `make()` 的问题。`a` 在 `make` 的栈帧里，`make` 一返回，栈指针弹回去，那块地方随时会被下一次函数调用覆盖。`main` 里再读 `p[0]`，读到的可能是 1，也可能是被 `printf` 自己的栈帧覆盖后的垃圾。它不崩只是运气。

也解释了递归的问题。每层都要一个新栈帧，深度乘以单帧大小就是总开销。`pad[100]` 让单帧变成一百多字节，一万五千层就是 2 MB 左右，超过 1 MB 的默认栈，进程被杀。

## 两个常见误解

**"尾递归会被优化成循环"。** C 标准没有这个要求，gcc 在 `-O2` 下有时会做尾调用优化，但你不能依赖它，而且带局部数组、带复杂清理的函数基本不会被优化。写竞赛代码时，把"靠编译器优化递归"当成赌博。

**"函数返回后局部变量的内存就释放了，所以肯定读不到"。** 释放只是"标记为可用"，值还在原地。这是一类非常隐蔽的 bug：程序在调试机上一直正常，到了评测机上换了个调用顺序就崩了。

## 处方

1. 不要返回局部变量的地址。要返回就三条路：调用者传 buffer 进来、用 `static`（注意不可重入）、用 `malloc`（记得让调用者 `free`）。
2. 写递归先估深度。单帧几十到几百字节，一万层大致对应 1 MB。深度可能过万，就改写成显式栈的迭代版本。
3. 大数组别放栈上。这是第 01 例的结论，在这里得到了机制上的解释：栈只有 1 MB，堆和 BSS 大得多。
4. 深搜（DFS）在网格题里很容易爆栈。100×100 的迷宫最深一万步，每帧几十字节，就在边界上。改成 `while` + 自己维护的栈数组更稳。
5. 需要看清栈可以看调用栈：Dev-C++ 调试时打开 Call Stack 窗口，崩在哪一层一目了然。
