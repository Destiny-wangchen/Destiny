## 主诉

```c
char buf[16];
printf("%s\n", buf);
```

这段代码编译没有任何警告，运行也不崩，就是输出一串看不懂的字符。有时候是几个方块，有时候是几个汉字，有时候什么都没有。

同一个程序，今天跑和明天跑结果还不一样。有人管这叫"随机值"，甚至以为是编译器在捣乱。

## 化验

```c
#include <stdio.h>

int main(void)
{
    char buf[16];
    int i;
    unsigned char *p = (unsigned char *)buf;

    printf("前 8 个字节: ");
    for (i = 0; i < 8; ++i)
        printf("%02X ", p[i]);
    printf("\n");

    char s[8];
    s[0] = 'h'; s[1] = 'i'; s[2] = '!';
    printf("忘了写 \\0: %s\n", s);
    return 0;
}
```

我这台机器上：

```text
前 8 个字节: 28 7A 40 00 00 00 00 00
忘了写 \0: hi!
```

第一行里，`buf` 一个字节都没赋值，但内存里不是空的，前四个字节是 `28 7A 40 00`，看起来像某个地址的低半截。第二行看着"正常"，其实只是运气好：`s[3]` 后面恰好是个 0，`%s` 就停在那儿了。

换个编译器、换个函数、甚至改一行无关的代码，这两行输出都会变。

## 诊断：栈上的内存是租来的，房东不清房

`char buf[16]` 只是让栈指针往下挪 16 字节，并没有往这 16 字节里写任何东西。这块地方之前属于谁？可能是上一个函数调用的局部变量，可能是某个返回地址，可能是栈上放过的参数。函数返回时栈指针弹回去，但里面的数据没人擦，下一个人搬进来就直接住。

所以"未初始化变量"读到的永远是**上一任住户的遗留**。它看起来随机，其实完全确定，只是取决于你之前跑过什么。

全局变量不一样。没初始化的全局变量落在 BSS 段，程序加载时由操作系统整块清零，所以按标准它们就是 0。这也是为什么很多竞赛代码把大数组开成全局：既避免了栈溢出，又顺便拿到了全 0 的初值。这条在第 01 例里已经用过一次。

那"烫烫烫"呢？那是 Microsoft 的编译器在调试模式下把未初始化的栈填成 `0xCC`，两个字节 `CC CC` 在 GBK 里正好是"烫"。这是调试填充，**不是标准**，MinGW 和 Linux 上的 gcc 都不保证有。所以看到"烫烫烫"能判断"你用了没初始化的内存"，看不到不代表没问题，我上面那行 `28 7A 40 00` 就是同一类问题。

## 最危险的一种：忘了 `\0`

字符串比普通数组多一条规矩：必须以 `\0` 结尾。`strlen`、`printf("%s")`、`strcpy` 全靠这个 0 判断结尾，找不到就继续往下读。

往下读的后果，轻则多打印几个乱码，重则读出整片栈，把别的变量的值、甚至返回地址打印出来。在别人的机器上，这可能直接变成崩溃。

```c
char s[8];
s[0] = 'h'; s[1] = 'i'; s[2] = '!';   /* 少了 s[3] = '\0' */
printf("%s\n", s);                     /* 读到哪儿算哪儿 */
```

`strncpy` 也有坑：源串长度达到上限时它不补 `\0`，你以为复制好了，其实是个没有结尾的串。

## 处方

1. 定义时就初始化。`char buf[16] = {0};` 或 `char buf[16] = "";`，零成本，一次写对。数组用 `= {0}` 会把全部元素清零。
2. 读字符串用 `fgets(buf, sizeof(buf), stdin)`，它会保证结尾有 `\0`；`gets` 早就从标准里删掉了。
3. 打印不一定非要结尾时，用精度限定：`printf("%.16s", buf)` 最多打 16 个字节，不会越界。
4. 复制前先算好长度，用 `snprintf` 或 `memcpy` 加手动补 0，别指望 `strncpy` 帮你收尾。
5. 想在开发期抓这类问题，编译时加 `-Wall -Wextra`，Linux 上用 AddressSanitizer（`-fsanitize=address`），它会在越界读的那一刻直接报出来，比看乱码强得多。

## 一个判断技巧

看到输出里出现"每个字符都是同一个方块"或者明显的地址样式，基本可以断定是读了没初始化的内存。反过来，如果输出每次都一样、换机器就变，那多半也是这个原因，而不是逻辑错。

判断方法很简单：在定义之后加一行 `memset(buf, 0, sizeof(buf))`，如果输出变正常了，问题就定位了。
