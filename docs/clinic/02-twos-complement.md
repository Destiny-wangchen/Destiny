## 主诉

一个同学跑来找我，说他的程序"算着算着变成负数了"。程序很简单：读一批成绩，累加，最后除以人数。人少的时候一切正常，人一多，平均分就变成 `-2147483648`。

他自己也查过，说加起来的总分明明是正数，怎么打印出来是负的。我让他把总分单独打出来，果然是个负数。

类似的症状还有几个：`char c = 200;` 打印出来是 `-56`；两个正数加起来却比其中任何一个都小；`while (i < n)` 的循环跑着跑着停不下来。

它们住院的原因都一样。

## 化验：四个数

先写一段不涉及任何业务逻辑的小程序：

```c
#include <stdio.h>
#include <limits.h>

int main(void)
{
    int a = INT_MAX;
    printf("INT_MAX        = %d\n", a);
    printf("INT_MAX + 1    = %d\n", a + 1);
    printf("-5 as unsigned = %u\n", (unsigned)-5);
    printf("-5 as hex      = %08X\n", (unsigned)-5);
    printf("(char)200      = %d\n", (char)200);
    printf("(short)70000   = %d\n", (short)70000);
    return 0;
}
```

我这台机器上（Windows + MinGW）的输出：

```text
INT_MAX        = 2147483647
INT_MAX + 1    = -2147483648
-5 as unsigned = 4294967291
-5 as hex      = FFFFFFFB
(char)200      = -56
(short)70000   = 4464
```

四个结果，四个不同的疑惑点。

`INT_MAX + 1` 变成最小的负数。`-5` 当作无符号数是四十二亿多。`-5` 的十六进制是 `FFFFFFFB`。`200` 存进 `char` 变成 `-56`。`70000` 存进 `short` 变成 `4464`。

## 诊断：只有一种加法，叫模运算

C 语言的整数不是数学里的整数，它是**固定宽度的位容器**。`int` 有 32 个格，`char` 有 8 个格，`short` 有 16 个格。每次运算的结果，超过宽度就从头上掉出去，不从另一边补回来。

`INT_MAX` 是 `0111...1111`（31 个 1）。加 1 得到 `1000...0000`，最左边那位本来是符号位，现在变成了 1，于是这个数按补码解释就是 `-2147483648`。没有"溢出报错"这回事，位容器满了就是这样。

`char` 是 8 位。200 的二进制是 `11001000`，最高位是 1，按补码读就是 `-56`。想存 200 得用 `unsigned char`（0～255）。`short` 存 70000 同样的道理，70000 减掉 65536 剩下 4464。

`-5` 为什么是 `FFFFFFFB`？补码的定义是**取反加一**：5 是 `0101`，取反 `1010`，加一 `1011`，扩到 32 位就是 `...11111011`。当无符号读，它就是 2³² − 5 = 4294967291。

这里有个很多人没想通的点：**同一串位，符号不同，值就不同**。`FFFFFFFB` 这串位既可以是 -5，也可以是 4294967291，取决于你用 `%d` 还是 `%u` 去读它。所以 `printf` 的格式符写错，打印出来就是另一个数，程序本身没错。

## 三个真实后果

**第一个，求和溢出。** 30 万个成绩，每个不超过 100，总和最多 3000 万，`int` 装得下。但如果统计的是毫秒数、字节数、路径条数，十万级的输入乘起来就过 21 亿了。症状就是开头那个 -2147483648。

**第二个，无符号的下溢。** 这个更阴。`unsigned int i = 0; i--;` 不会变成 -1，会变成 4294967295，然后 `while (i >= 0)` 永远成立。无符号数没有负数，循环条件永远为真。

**第三个，有符号和无符号混着比。** `int a = -1; unsigned b = 1; if (a < b)` 这句在某些情况下会判成假，因为比较前 `a` 被转成了无符号，`-1` 变成 4294967295，当然比 1 大。编译器通常会给个 `-Wsign-compare` 警告，很多人把它当噪音关掉。

## 处方

1. 先估范围再选类型。10⁵ 个 10⁵ 量级的数求和，用 `long long`（上限 9.2×10¹⁸），别省这 4 个字节。规则很简单：**中间结果可能超过 21 亿，就用 `long long`**。
2. `printf` 的格式符跟着类型走。`long long` 配 `%lld`，`size_t` 配 `%zu`，`unsigned` 配 `%u`。格式符写错时编译器在 `-Wall` 下会提醒你。
3. 需要计数的变量别用无符号。倒着数的循环（`for (i = n-1; i >= 0; --i)`）用 `int`，用 `unsigned` 会在 `i = 0` 之后变成天文数字。
4. 混比较时显式转换，或者干脆统一成有符号。把 `-Wsign-compare` 打开，别关。

## 一个常见误诊

有人看到负数，第一反应是"内存坏了"或者"编译器有 bug"。这类问题几乎都能用一行 `printf` 排除：把中间结果按 `%d` 和 `%u` 各打一遍，再打一遍 `%lld`，三个数一比，就知道是宽度不够还是符号读错。

另外提醒一句，有符号溢出在标准里是**未定义行为**，编译器理论上可以做任何事，包括把 `if (a + 1 < a)` 这种判断直接优化掉。我上面写的 `INT_MAX + 1` 在 MinGW 下稳定输出 -2147483648，但你不能依赖这个结果，正确做法是别让它溢出。
